# Especificações

Cada iniciativa começa por requisitos e critérios observáveis, não por código. Cada funcionalidade deve ter uma SPEC própria ou estar vinculada claramente a uma SPEC existente. Usar `templates/specifications/specification-template.md` e versionar status, autor/responsável, data e referências.

Incluir objetivo, contexto, escopo/exclusões, requisitos funcionais, regras de negócio, requisitos não funcionais e de segurança, integrações, critérios de aceite verificáveis e dúvidas/decisões pendentes. Marcar claramente fato confirmado, hipótese e pendência. Obter aprovação dos requisitos antes do plano detalhado. Não copiar especificações de projetos de clientes.
